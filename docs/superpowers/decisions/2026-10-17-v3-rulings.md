Per-task internal agreement: Tasks 1–12 each checked — the gates each task
specifies match the files it says it will touch. Two exceptions, both
recorded above as Rulings A and B.

Ruling A: banned-vocabulary gates (PAPER in Task 3, FETCH_AS_LIVESTOCK in
Task 4, COLD_ARM in Task 6) are scoped to `("lore", "factions")` when first
written, and Task 11 widens them to the whole tree and fixes what they then
name. — Why: a gate that fails on files its own task does not own blocks that
task on another task's work, and a growing exemption list is worse than an
explicit scope. — Cost if wrong: Task 11 becomes the big sweep, which it
already is; no content escapes, because Task 11 widens every gate.

Ruling B: `test_no_lore_id_is_lost_or_changed` asserts that no frozen id is
lost or changed — subset semantics with an explicit REMOVED set — not that
the id set is immutable. — Why: five later tasks legitimately create new lore
files, and set equality would fail every one of them. — Cost if wrong: a
spurious new id could be added unnoticed; the sync in Task 12 fails loudly on
any id mismatch, so it is caught there.
